# 02. K-타로 리딩 풍성화 설계

> 작성 2026-10-08 · 대상 `apps-in-toss/` (miniAppId 77288)
> 입력 문서: `K-타로 78장 구조화 노트.md`, `K-타로 오리지널 해석 문안.md` (둘 다 리포 루트)
> 상태: **설계 — 승인 대기**

---

## 0. 지금 리딩이 빈약한 진짜 이유

`src/content/ko/tarot.ts` 전문을 보면 원인이 분명하다.

```ts
export function dailyReadingKo(card: TarotCard, element: WuXing): string {
  const el = elementLabel(element, "ko");
  return `오늘 당신의 카드는 '${card.name_kr}' — ${SUIT_NUANCE[card.suit]}의 카드예요. ${el}의 기운을 믿고 나아가면 좋은 일이 따라올 거예요. ✨`;
}
```

**카드가 기여하는 건 이름뿐이다.** 나머지는 수트(5가지) × 오행(5가지)에서 온다.
즉 78장을 뽑아도 실제로 만들어지는 문장은 **최대 25종**이고, 같은 수트면 뒷문장이
글자 하나까지 같다. 3장 스프레드도 같은 구조다.

카드 데이터에 `theme`·`keywords` 가 있긴 한데 **영어**이고(`"a free spirit, unbound"`),
한국어 리딩에서는 아예 쓰지 않는다.

→ 새 문서 두 개가 정확히 이 구멍을 메운다.

---

## 1. 입력 문서에서 쓸 수 있는 것

| 문서 | 범위 | 담긴 것 |
|---|---|---|
| 78장 구조화 노트 | **78장 전부** | 정방향 키워드 3 · 역방향 키워드 3 · 핵심 상징 · 한국풍 모티프 메모 |
| 오리지널 해석 문안 | **메이저 22장만** | 정/역 본문, 연애·일·돈·조언 3줄, 모티프 훅, 한국식 카드명 |

구조화 노트는 수트 ↔ 오행 대응도 준다:
완드=화 / 컵=수 / 소드=금 / 펜타클=토, **메이저=목(木)**.

해석 문안은 스스로 핸드오프 JSON 스키마까지 제시한다(`id`/`slug`/`keywords`/
`reading`/`topics`/`motifHook`). 그 스키마를 그대로 따른다.

### ⚠️ 비대칭이 설계를 가른다

**메이저 22장만 본문이 있고 마이너 56장은 키워드뿐이다.** 문서 마지막 줄도
"마이너 56장 문안은 같은 형식으로 이어서 쓸 수 있어요"로 끝난다.
→ 72%의 카드는 본문이 없다. 설계가 이걸 전제로 우아하게 무너져야 한다.

## 2. 결정적 제약 — 카드 이름을 바꿀 수 없다

덱 아트를 직접 열어봤다. 이미 한국풍이다(봇짐·한복·탈·단청·모란).
**그런데 카드 이름이 이미지에 구워져 있다.**

- `major-00-fool.webp` → 배너에 `The Fool (광대)`
- `cups-ace.webp` → 배너에 `Ace of Cups (잔의 에이스)`

해석 문안이 제안하는 원작 IP명("떠돌이 보부상", "방울 든 도사")으로 **표시 이름을
바꾸면 그림 속 글씨와 어긋난다.** 사용자는 "떠돌이 보부상"이라는 제목 아래
"The Fool (광대)"라고 적힌 그림을 보게 된다.

**→ 표시 이름은 `name_kr`(광대) 그대로 둔다.** 원작 이름은 **부제**로만 쓴다:

```
          광대
   떠돌이 보부상 · 봇짐 하나면 충분한 날
```

이러면 IP 작명을 버리지 않으면서 그림과도 어긋나지 않는다.
덱 아트를 다시 만들면 그때 표시 이름을 승격하면 된다.

## 3. 데이터 설계

### 3.1 새 파일 하나만 추가한다

`src/data/ktarot-ko.json` — 기존 카드 `id`(0~77)를 키로 하는 **한국어 보강 레이어**.

```jsonc
{
  "0": {
    "alias": "떠돌이 보부상",
    "up":  ["출발", "순수", "모험"],
    "rev": ["무모함", "망설임", "방향 상실"],
    "symbol": "절벽 끝, 보따리, 흰 개",
    "motif": "봇짐 멘 떠돌이 소년 보부상, 삽살개 동행",
    // 메이저 22장만 ↓
    "reading": { "up": "봇짐 하나면 충분한 날이에요. …", "rev": "신발 끈이 풀린 채 …" },
    "topics": { "love": "…", "work": "…", "advice": "…" },
    "hook": "삽살개가 먼저 고개를 돌린 쪽이 오늘의 방향."
  },
  "22": { "up": ["영감","시작의 불씨","의욕"], "rev": [...], "symbol": "…", "motif": "…" }
}
```

- `src/data/ksaju-tarot.json`(78장 원본)은 **건드리지 않는다.** 4개 로케일을 쓰는
  웹앱과 모양을 공유하므로 영어 필드를 바꾸면 양쪽이 틀어진다. 보강은 덧붙이기만 한다.
- 메이저는 `element`가 `null` 이다 → 구조화 노트의 **메이저=목(木)** 대응으로 채운다.
  지금은 메이저를 뽑으면 오행 문장이 비거나 엉뚱한 값으로 떨어진다.

### 3.2 손으로 옮기지 않는다 — 생성기를 쓴다

`scripts/gen-ktarot.mjs` (`npm run gen:ktarot`)가 두 `.md` 를 파싱해 JSON 을 만든다.
리포에 이미 있는 패턴(`seed-idols.mjs`, `gen-assets.mjs`)과 같다.

- 78장 표 + 22장 섹션을 각각 읽어 카드 `id` 로 합친다
- **검증 후 기록**: 78개 전부 채워졌는지, 메이저 22개에 본문이 있는지, 키워드가
  정확히 3개인지 확인하고 하나라도 어긋나면 **쓰지 않고 멈춘다**
- 멱등 — 문서를 고치고 다시 돌리면 그만큼만 바뀐다
- 원본 `.md` 2개는 `docs/` 로 옮겨 같이 커밋한다(출처를 리포 안에 둔다)

용량: 원문 29KB → JSON 약 25KB, gzip 약 8KB. `data-tarot` 는 이미 **지연 청크**라
(19.2KB) 첫 화면 비용이 0이다. `.ait` 0.28MB 예산에 영향 없음.

## 4. 리딩 조립 설계

`src/content/ko/ktarot.ts` 신설. 기존 `tarot.ts` 의 두 함수를 대체한다.

### 4.1 메이저 22장 — 작성된 본문을 그대로

```
오늘의 카드 · 광대 (떠돌이 보부상)
[정방향]

봇짐 하나면 충분한 날이에요. 완벽한 지도보다 첫걸음이 길을 만들어 줄 거예요.

💗 연애   계산 없이 웃게 되는 사람이 신호예요.
💰 일·돈  작게 시작해 보는 실험이 유리해요.
🌿 조언   안 가본 길로 한 블록만 걸어보세요.

— 삽살개가 먼저 고개를 돌린 쪽이 오늘의 방향.
```

### 4.2 마이너 56장 — 카드별 키워드로 조립

본문이 없으므로 **카드 고유 키워드 + 모티프**로 만든다. 지금(수트 공용 문장)보다
확실히 나아진다. 수트가 아니라 **카드**가 문장을 결정한다.

```
오늘의 카드 · 잔의 에이스
[정방향]

'새 감정'이 열리는 자리예요. 사랑의 시작, 충만으로 이어지는 흐름이고,
연꽃 위 막사발에서 정화수가 넘치는 그림처럼 넘칠 만큼 차오르는 때예요.

🌿 조언   수(水)의 기운을 믿고 마음이 가는 쪽을 한 번 더 들여다보세요.
```

- 키워드 3개를 문장 틀에 끼우고, 모티프 메모를 뒷문장으로 쓴다
- 조언 한 줄은 수트의 오행으로 만든다(기존 자산 재사용)
- 문장 틀은 수트별로 2~3개 두어 같은 수트가 연달아 나와도 반복감이 덜하다

### 4.3 3장 스프레드

각 카드마다 4.2 방식의 **한 줄 요약**(키워드 중심) + 자리별 프레이밍(과거/현재/미래),
마지막에 세 장의 키워드를 엮은 `synthesis` 한 줄. 메이저가 끼면 그 카드의 `hook` 을
덧붙인다.

## 5. 정방향 / 역방향 — 제안하되 결정 필요

구조화 노트는 **78장 전부** 역방향 키워드를, 해석 문안은 **메이저 22장** 역방향
본문을 이미 갖고 있다. 즉 데이터는 준비돼 있다.

**넣자고 제안하는 이유:** 하루 한 장 상품인데 지금은 카드당 결과가 하나다.
정/역을 넣으면 같은 카드를 다시 뽑아도 다른 이야기가 나온다 —
**D1 리텐션이 0%인 앱에 재방문 이유를 하나 더 주는 가장 싼 방법이다.**

문서가 톤 규칙으로 못을 박아 뒀다:

> 역방향도 저주가 아니라 "속도 조절 신호"로 풀어서, 부정 카드를 뽑아도 재방문하고 싶게 만들어요.

**방향 결정 방식**
- 오늘의 카드: 기존 시드의 다른 비트로 결정 → 같은 사람·같은 날이면 고정
- 3장 스프레드: 뽑을 때 카드별로 결정

**이미지는 뒤집지 않는다.** 실물 덱은 역방향이면 그림도 뒤집히지만, 이 덱은
**카드명이 그림에 구워져 있어** 180° 돌리면 글씨가 거꾸로 선다. 대신 `역방향` 배지를
제목 옆에 둔다.
