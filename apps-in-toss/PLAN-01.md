```

App.tsx:132    <TabNav … />
App.tsx:133    {active && <BannerAd adGroupId={BANNER_AD_GROUP_ID} />}
```

- 앱 전체에 `<BannerAd>` 인스턴스는 **1개**다. "나머지 제거" 대상이 없다.

  이미 `{active && …}` 로 사주를 본 뒤에만 뜨지만, 스크롤과 무관하게 항상 떠 있다.
- **00 E1 위반 동시 확인**: `TabNav` 와 간격 **0** 으로 붙어 있다(SSP 오클릭 정책).

**(a) 권고** — (b)는 승인된 노출 구성을 바꾸는 것이고, 배너가 화면 밖으로 나가
노출량이 떨어진다. 지시의 의도("광고 1개만")는 이미 충족돼 있다.

## 2. 4번 전환 이벤트 — `reading_complete` 를 넣으면 안 되는 이유

현재 콘솔 전환 지표(9/25부터 집계 중):

| 지표 | 로그 이름 | 상태 | 최근 7일 |
|---|---|---|---|
| 내 사주 결과 확인 | `saju_result` | **MAIN** | 104 |
| 오늘의 타로 확인 | `tarot_result` | SUB | 27 |
| 공유 카드 저장 | `share_saved` | SUB | 5 |

**대표(MAIN) 지표는 삭제할 수 없다.** 그리고 지표는 로그 이름 문자열에 묶여 있다.

지시대로 `reading_complete {type}` 으로 통합하면:
`saju_result` 발신이 끊기고 → **대표 지표가 영구히 0** → 10/22 '추천' 선정의
전환율 계산이 불가능해진다. 되돌릴 방법이 없다(삭제 불가).

### 대안

- [ ] `reading_complete` **넣지 않는다.** 이미 `saju_result`/`compat_result`/
      `tarot_result` 가 같은 일을 하고 있고, 이름만 바꾸는 비용이 비가역이다
- [ ] `daily_fortune_open` **추가** — 신규 이름, 충돌 없음. 지금 운세 카드 조회가
      전혀 계측되지 않는다
- [ ] `detail_unlock` — Phase 2 로 이월 (상세 풀이가 생겨야 발생하는 이벤트)
- [ ] 콘솔 **지표 등록은 보류**. 전환 지표 권장 상한이 3개이고 이미 3개다.
      로그는 먼저 쌓아두고(로그는 무제한), 수치가 의미 있으면 그때 SUB 하나와 교체

## 4. Phase 2 — 결과 2단 + 보상형 광고 (지시 1)

**반나절로 불가능하다.** 근거를 적는다.

### 4.1 선행 작업이 코드 밖에 있다

- [ ] 콘솔에 **보상형 광고 그룹 신설** (`iaa_placement_group_create`, adFormat REWARDED)
  - ⚠️ **전면형(INTERSTITIAL) 그룹으로 만들면 `userEarnedReward` 가 영원히 발화하지
    않는다.** 적립을 그 이벤트에 걸면 조용히 0 지급이 된다 — 광고 코어 스킬이
    "가장 비싼 실수"로 기록한 항목이다. 반드시 REWARDED 로 만든다
- [ ] 심사 재제출 1사이클 (과거 13분~17시간)

### 4.2 광고 코어 이식이 필요하다

이 앱에는 전면형·보상형 호출부가 0개다. 보상형을 넣는 순간 **같은 화면에 배너와
보상형이 공존**하므로, 검증된 광고 코어의 불변식이 전부 걸린다:

- 전면형 로드와 배너 로드 **동시 in-flight 금지** (Android 5.266.0+ 에서 전면형
  이벤트 100% 유실 — 현재 ACTIVE 긴급패치)
- `rewardCritical` show 중 배너 로드 보류 (적립 이벤트 보호)
- `load → loaded 수신 → show` 순서 강제
- 완료 판정은 **`userEarnedReward` 만** — `dismissed`/`impression` 으로 판정 금지
- 시청 완료를 타이머로 추측 금지 (30초~1분 보상형을 N초로 오판한 실사고)
- 모든 광고 CTA 에 대기 모달 배선 (빠지면 "눌러도 무반응" CS)

스킬이 레퍼런스 구현과 골든 테스트 44개를 제공하지만, **추측으로 재작성 금지**이고
이식 체크리스트가 7단계다. 현실적으로 **2~3일**.

### 4.3 제품 리스크 — 지금 무료인 것을 광고 뒤로 숨기는 일이다

현재 사주 결과는 **전부 무료**다: 일간 유형 / 4기둥 / 오행 균형 / 오늘의 운세 4카드
(`MySajuScreen.tsx:151-162`). 지시의 2단 구조는 이 중 상세를 광고 뒤로 옮기는 것이다.

1. **기존 사용자에게는 기능 축소다.** 9/21 출시 후 쌓인 사용자가 어제 무료로 본 것을
   오늘 광고를 봐야 보게 된다.
2. **유입이 전부 혜택탭이다** (DAU 의 83~90%). 포인트 받으러 온 사용자에게 광고
   게이트를 세우면 D1 리텐션이 더 떨어진다 — 이미 9/23 코호트 D1 이 **0%** 다.
3. **광고 타이밍으로 두 번 반려된 이력**이 있고, 직전 승인은 "광고 노출 방식은 직전
   승인 버전과 동일합니다"를 근거로 통과했다. 15일 뒤 심사 앞에서 이 근거가 사라진다.

### 4.4 Phase 2 를 할 때의 설계 (승인 시)

- [ ] 무료 요약 3줄은 **기존 무료 범위를 줄이지 않는 선**에서 잡는다 —
      지금 있는 것을 숨기는 대신 **새로운 상세 풀이(연애/재물/건강)를 신설**해
      그것만 광고 뒤에 둔다. 기능 축소가 아니라 추가가 된다
- [ ] 당일 재열람 무광고: 잠금 해제를 `Storage` 에 `{date, unlocked}` 로 기록
      (localStorage 아님 — 신규 데이터라 async 전환 비용 없음)
- [ ] 거절/실패 시 **요약은 그대로 남고 데드엔드 없음** (완료 기준)
  - [ ] `dismissed`(미시청 종료) → 요약 유지 + "다음에 볼게요" 로 복귀
  - [ ] `failedToShow`/`onError` → 요약 유지 + 재시도 버튼
  - [ ] `isSupported() === false`(구버전 토스) → **상세를 그냥 무료 공개**.
        광고를 못 보는 사용자를 막아선 안 된다
- [ ] `detail_unlock` 이벤트는 `userEarnedReward` 수신 시에만 발신

## 7.2 진단 — 공유가 안 되는 이유 3가지 (코드 근거)

### ① 진짜 공유 경로가 '자기파괴 카드' 안에 1곳만 있다

```
grep -rn "shareMiniApp"  →  src/components/PromotionCard.tsx  (유일)
```

`shareMiniApp()`(토스 공유 시트 = 신규 유입이 생기는 유일한 경로)은 `PromotionCard`
에서만 호출된다. 그런데 그 카드는 설계상 **미션 완료·거절 후 영구 소멸**한다
(2.5초 후 자동 닫힘 + 완료자에게 재렌더 안 함).

결과: **재방문자에게 공유 경로가 0개다.** 바이럴은 충성 사용자가 반복해서 퍼뜨려야
생기는데, 정확히 그 사용자에게 버튼이 없다.

### ② 눈에 띄는 버튼은 '공유'가 아니라 '사진첩 저장'이다

```
MySajuScreen.tsx  →  "이미지로 저장하기 ✨"  →  saveShareCard()  →  saveBase64Data
```

`saveShareCard`는 PNG를 **사용자 사진첩에 쓰고 끝난다.** 아무도 받지 않는다.
사용자가 직접 인스타·카톡을 열어 올려야 하고, 그 뒤는 측정조차 못 한다.

→ **`share_saved` 7일 5건은 '공유 5번'이 아니라 '저장 5번'이다.** 실제 공유 수는
우리가 아는 값이 아니고, 아마 그보다 적다.

### ③ 공유 링크에 미리보기 이미지가 없다

```ts
// toss-share.ts — 지금
const link = await getTossShareLink("intoss://ksaju");   // ogImageUrl 없음
await share({ message: `${message}\n${link}` });
```

3.5.0 타입 확인 결과:

- `Share.sendMessage({ message })` — **텍스트 전용. 이미지 첨부 불가**
- `Share.createLink({ path, ogImageUrl })` — **`ogImageUrl` 지원** (Android 5.240.0+, iOS 5.239.0+)

지금은 `ogImageUrl`을 비워 보내므로, **그림이 핵심인 앱의 공유 링크가 맨 링크로
돌아다닌다.** 사주·타로는 비주얼로 설득되는 콘텐츠인데 그 그림이 전달되지 않는다.

## 7.3 배치 권고 (효과/비용 순)

### 1순위 — 결과 화면 1차 버튼을 '공유'로 교체 ⭐

```
지금:  [ 이미지로 저장하기 ✨ ]                 ← 1차, 유일
제안:  [ 친구에게 보내기 ]                      ← 1차 (진달래, 보상 문구 포함)
       [ 이미지 저장 ]                          ← 2차 (텍스트 버튼)
```

- 사주 결과를 **다 읽은 직후** = 만족도 최고점. 보상 고지가 자연스러운 유일한 지점
- 보상이 남아 있으면 "친구에게 보내면 20원", 소진/수령 완료면 **문구만 빼고 버튼은 유지**
- 사진첩 저장을 없애지 않는다 — 인스타 스토리에 올리는 사용자를 막으면 안 된다

### 2순위 — 공유 링크에 `ogImageUrl` 부착 ⭐

- `getTossShareLink` → `Share.createLink({ path, ogImageUrl })`
- OG 이미지는 **ksaju.me 에 올린 정적 브랜드 이미지** 1장 (이미 `/tarot-webp` 를
  CORS 로 서빙하는 도메인이라 추가 인프라 0)
- 개인 결과 카드를 올리려면 호스팅이 필요하다 → **"외부 통신 0" 원칙과 충돌하므로 안 한다.**
  정적 이미지로도 "맨 링크"에서 벗어나는 효과가 가장 크다
- 구버전 토스(5.239/5.240 미만)는 `ogImageUrl` 이 무시될 뿐 깨지지 않는다

### 3순위 — 공유 카드 모달의 '저장 완료' 직후

- 지금 모달은 저장 후 **아무 데도 가지 않는다**(데드엔드)
- 카드를 저장한 사용자는 공유 의도가 이미 확인된 사람이다. 여기에 공유 CTA를 둔다
- 모수는 작지만(7일 5건) 전환율은 가장 높을 자리

### 4순위 — 프로모션 카드의 공유 CTA를 소멸시키지 않는다

- 보상 수령·거절 후에도 **공유 버튼은 남긴다.** 단 보상 문구는 제거
- 보상 카드 자체는 지금처럼 닫되, 공유 CTA는 1순위(결과 화면)로 이전하는 것이 깔끔하다
  → 1순위를 하면 4순위는 자동 해결된다

## 8.3 알림 10원 — **서버가 선행이다. Phase 1 범위 밖**
