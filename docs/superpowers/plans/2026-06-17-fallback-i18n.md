# Localized Fallback Readings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the tarot and daily-fortune *fallback* readings respect the request `locale` (en/ko/ja/zh-TW) so non-English users get localized text even when the LLM is unavailable.

**Architecture:** Two independent fallback functions become locale-aware. Tarot uses a 4-locale template map inside `tarotFallbackReading`, deriving the element word from existing `WUXING_META` (`.label` for en, `.hanja` for CJK). Daily-fortune moves its inline English `FALLBACK` into a committed `data/*-i18n.json` (following the codebase's existing i18n-data convention) and indexes it by locale. The LLM happy path is untouched — it already localizes.

**Tech Stack:** TypeScript, Next.js 16 route handlers, vitest. No new npm packages.

## Global Constraints

- **No new npm packages.**
- **English output must be unchanged** (byte-for-byte) — no regression for `en` or unknown locales.
- **Supported locales:** `en`, `ja`, `ko`, `zh-TW`; unknown → `en`.
- **Do not touch the LLM happy path** (prompt / `LANG_MAP` / OpenRouter call).
- **Card themes stay English-only** — omitted from non-English tarot fallback templates.
- **Out of scope:** restoring the Vercel `OPENROUTER_API_KEY` (user's operational action).
- Every commit message ends with a trailer line: `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`.
- After each task: `npm test` and `npx tsc --noEmit` must pass.

- **Replace** the existing `tarotFallbackReading` function with:
```typescript
const FALLBACK_LOCALES = ["en", "ko", "ja", "zh-TW"] as const;

/** Static reading used when the LLM/DB is unavailable. Localized by `locale`. */
export function tarotFallbackReading(card: TarotCard, element: WuXing, locale: string = "en"): string {
  const loc = (FALLBACK_LOCALES as readonly string[]).includes(locale) ? locale : "en";
  const meta = WUXING_META[element];
  switch (loc) {
    case "ko":
      return `오늘 당신의 카드는 '${card.name_kr}'. ${meta.hanja} 기운을 믿고 나아가면 좋은 일이 따라올 거예요. ✨`;
    case "ja":
      return `今日のあなたのカードは「${card.name_en}」。${meta.hanja}のエネルギーを信じて進めば、きっと良いことが訪れます。✨`;
    case "zh-TW":
      return `你今天的牌是「${card.name_en}」。順著你的${meta.hanja}能量前行，好事自然會來。✨`;
    default:
      return `${card.name_en} is your card today — ${card.theme}. Let your ${meta.label} energy lead the way, and good things will follow. ✨`;
  }
}
```

- [ ] **Step 2: Write the data-integrity test**

```typescript
import { describe, it, expect } from "vitest";
import fallback from "../../data/ksaju-daily-fortune-fallback-i18n.json";

const RELATIONS = ["combo", "same", "generate-me", "i-generate", "control", "neutral"];
const LOCALES = ["en", "ko", "ja", "zh-TW"];

describe("ksaju-daily-fortune-fallback-i18n.json", () => {
  it("has all 6 TimeRel relations", () => {
    expect(Object.keys(fallback).sort()).toEqual([...RELATIONS].sort());
  });

  it("each relation has numeric energy + all 4 locales for message and lucky_color", () => {
    for (const rel of RELATIONS) {
      const entry = (fallback as Record<string, { energy: number; message: Record<string, string>; lucky_color: Record<string, string> }>)[rel];
      expect(typeof entry.energy).toBe("number");
      for (const loc of LOCALES) {
        expect(entry.message[loc]?.length).toBeGreaterThan(0);
        expect(entry.lucky_color[loc]?.length).toBeGreaterThan(0);
      }
    }
  });

  it("preserves the original English combo energy + color", () => {
    const combo = (fallback as Record<string, { energy: number; lucky_color: Record<string, string> }>).combo;
    expect(combo.energy).toBe(5);
    expect(combo.lucky_color.en).toBe("Hot Pink");
  });
});
```
